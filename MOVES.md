# MOVES.md — the ledger of structural changes

**Why this file exists:** several AIs work on this codebase at once, on several
machines. When code MOVES — a file renamed, a directory relocated, a repo split,
an alias changed — every session still holds the OLD path in its context. This
file is the shared memory: one entry per change, written **in the same commit
that performs it**, so `git pull` delivers the explanation to everyone
automatically.

## The rules

1. **Any structural move gets an entry here, in the same commit** that performs
   it. Moving `api/foo.js` → `api/lib/foo.js`? The commit that `git mv`s it
   also edits this file.
2. **Entry format** (newest first):

   ```markdown
   ### YYYY-MM-DD — <what changed>
   - **What moved:** from → to (or: nothing moved — topology/config changed)
   - **Why:** one or two sentences
   - **Still points at the old path:** files/tests/docs that need updating
     (check with `grep -rn '<old path>'`), or "none"
   - **Cleanup status:** done / pending — who's doing what
   ```

3. **Until everyone has pulled the move**, leave a stub at the old path when
   the old path is a directory or an entry point people type: a one-line file
   saying `MOVED → see MOVES.md`. A stub beats a missing file: the next
   session that looks for the old path finds the answer instead of assuming
   data loss.
4. **Read the newest entries first** before assuming any path is wrong.

## Entries (newest first)

### 2026-11-25 — ONE code repo: hivvz folded back into hivv (supersedes the entry below)

- **What moved:** `origin` on ashy: `htmlfarmer/hivvz` → **`htmlfarmer/hivv`**.
  The three-repo split below collapsed: `hivv` had become a *generated full
  mirror* of hivvz (to keep clone URLs / CI badge / issues working) — two
  byte-identical full copies is exactly the redundancy a mirror was meant to
  avoid. **`hivv` is THE canonical repo again**; `hivvz` is **ARCHIVED**
  (read-only; same branches, content identical at fold time — nothing lost).
  The duplicate `hivv` remote on ashy was removed (origin IS hivv now).
  The website projection `hivv.org` keeps its job — it is a different *view*
  of the same source, not a copy — and `scripts/sync-mirrors.sh` now only
  regenerates that half.
- **Why:** one source of truth, zero duplication — every existing clone URL,
  the CI badge, issue links and the CLI's self-heal string keep working with
  NO mirror step; no second full copy to sync, to scan, or to accidentally
  push to.
- **Still points at the old path:** machines whose `origin` still says
  `hivvz` — run on each clone:
  `git remote set-url origin git@github.com:htmlfarmer/hivv.git && git fetch --prune`
  (archived hivvz still FETCHES, but pushes are refused — loud, not silent).
  The deploy/sync origin rails and `tests/test_repo_scripts.py` fixtures now
  pin `htmlfarmer/hivv.git` and actively REFUSE a hivvz origin.
- **Cleanup status:** done on ashy (remotes · scripts · docs · tests);
  pending: the other machines' `origin` URLs (command above).

### 2026-11-25 — Repository topology: three repos, one source of truth

- **What moved:** nothing on disk. The git REMOTE topology changed:
  - `origin` on the ashy production tree now points at
    **github.com/htmlfarmer/hivvz** (was `htmlfarmer/hivv`).
  - **`hivvz` = THE canonical repo.** All development, all pushes, all clones.
  - **`hivv` = generated FULL mirror** of hivvz (every branch). It keeps every
    existing reference working: README clone URLs, the CI badge, issue links,
    `hivv`'s own README/CONTRIBUTING, and the CLI's self-heal message
    (`git clone …hivv.git` is pinned by `tests/test_cli_parser.py`).
  - **`hivv.org` = generated WEBSITE mirror** — `public_html/` becomes the
    repo root (plus a generated README + LICENSE). The placeholder
    "Initial commit" GitHub created is replaced by the first sync.
  - New remotes on this checkout: `hivv`, `hivv-org` (mirror targets).
- **Why:** six+ AIs on several machines (ashy · yalla · masjid · wahi …) were
  all pushing through ONE machine's checkout. GitHub is now the hub: clone
  `hivvz` anywhere, branch, push, PR/merge to `main`, then deploy to ashy with
  `scripts/deploy.sh`. Mirrors are generated by `scripts/sync-mirrors.sh` —
  **never push to `hivv` or `hivv.org` directly** (the full mirror makes the
  next sync fail loudly; the website mirror overwrites hand-commits).
- **Still points at the old path:**
  - `README.md` / `CONTRIBUTING.md` / `docs/INSTALL.md` / `docs/PARTNER-API.md`
    clone URLs say `htmlfarmer/hivv` — **intentional for now** (full mirror,
    the URLs work). Do NOT change them casually: `tests/test_cli_parser.py:117`
    pins the string in the CLI source. Switching the docs to `hivvz` is a
    coordinated change (docs + CLI + test in one commit).
  - **Other machines still have `origin → hivv`.** Run on each clone:
    `git remote set-url origin git@github.com:htmlfarmer/hivvz.git && git fetch --prune`
    (or just re-clone `hivvz`).
  - `public_html/bugs/index.html` queries GitHub issues on `htmlfarmer/hivv`
    — fine while issues live on `hivv`; if the issue tracker moves to `hivvz`,
    update that page in the same commit.
- **Cleanup status:** pending — (a) re-point the other machines' remotes,
  (b) decide whether issues/CI badge/clone URLs move to `hivvz` later,
  (c) the items below.

### 2026-11-25 — New tooling (not a move — the entry point for the above)

- **`scripts/deploy.sh`** — the only supported way to change production:
  rails (origin=hivvz · on main · clean tree · nothing unpushed) → fetch →
  `merge --ff-only` → new migrations (psql, setup.sh semantics) → `npm ci` if
  deps changed → pm2 restart → health poll → pytest gate. Red gate or dead
  health ⇒ automatic rollback (migrations are forward-only, NOT reverted).
  Flags: `--dry-run`, `--fast` (skip the test gate).
- **`scripts/sync-mirrors.sh`** — regenerates both mirrors from committed
  refs only, with an isolated `GIT_INDEX_FILE` (never disturbs a dirty tree or
  somebody's staged index). `--dry-run` supported. Refuses to run when
  `origin` isn't hivvz.
- **Workflow + topology docs:** `CONTRIBUTING.md` (contributor-facing),
  `AGENTS.md` §Repository topology (AI-facing), this file (the ledger).
