# Relocating a bee to another machine

> HIVV is pronounced **HIVE** (like a beehive).

A `git clone` brings the code. It does not bring the bee.

The bee's identity, its credentials and its state live in your home
directory, not in this repository:

| what | where | why it matters |
|---|---|---|
| the identity key | `~/.local/share/hivv/identity/ed25519.key` | **the bee.** A bee whose key did not travel is a new bee, and the hub sees a stranger |
| the public identity | `~/.local/share/hivv/identity/ed25519.pub` | the address peers use |
| the dial id | `~/.local/share/hivv/dial-id` | this bee's id on the network |
| the instance id | `~/.local/share/hivv/instance-id` | this installation's id |
| the env | `~/.local/share/hivv/hivv.env` | tokens — **never commit these** |
| the session secret | `~/.local/share/hivv/.session-secret` | signs session cookies |
| the hub credentials | `~/.config/hivv/auth.json` | who this installation is to the hub |
| the contribution prefs | `~/.config/hivv/contribute.json` | what this box offers |
| approvals | `~/.local/share/hivv/approvals.json` | what the agent has been allowed to do |
| tiles | `~/.local/share/hivv/tiles/` | the agent's working memory |

None of that is in git — and none of it should be. It is yours.

## The check

```bash
scripts/portability/node-state.sh
```

It reports every piece above, and for the secret ones it reports a
**fingerprint** rather than the value:

```
==> identity
  identity.pub               3VM5D8OyO2/AP/v1GGnVBnYHmfp6QNqJciJvoPqZfKY=
  identity.key               1048a24dde08
==> credentials (fingerprints, never values)
  auth.json                  6aca6217c52d
  hivv.env                   983ff851f93e
  session.secret             b6620ac9f967
```

Run it on the old machine, run it on the new one, and compare the
fingerprints. If `identity.key` matches, the right bee arrived.

The report is safe to paste into chat — it contains no secret, only
proofs.

## The move

On the **old** machine:

```bash
scripts/portability/node-state.sh > ~/bee-state-before.txt
```

Copy the state across. The whole thing is small:

```bash
scp -r ~/.local/share/hivv ~/.local/share/hivv.identity.bak   # keep a copy
scp -r ~/.config/hivv NEWBOX:~/.config/
scp -r ~/.local/share/hivv NEWBOX:~/.local/share/
```

On the **new** machine:

```bash
scripts/setup-local.sh --check        # is the code ready?
scripts/portability/node-state.sh     # did the state arrive?
```

Then install the CLI and start the agent:

```bash
curl -sSL https://hivv.org/install-hivv.sh | bash
hivv doctor
```

## Two bees, or one bee in two places?

This is the decision the move actually turns on.

**Two bees (recommended for capacity).** Give the new machine a FRESH
identity — do not copy `identity/`. Both machines register, both serve,
and the hive has two bees instead of one. The old one keeps its reputation
and its peers.

**One bee in two places (for failover).** Copy the identity as above, but
then **stop the old machine's agent before starting the new one**. Two
processes holding the same identity key is a split brain: the hub sees one
bee flapping between two addresses, and both halves answer with a state
the other half knows nothing about.

```bash
# on the OLD machine, before starting the new one
systemctl --user disable --now hivv-agent.service
systemctl --user disable --now hivv-dial.service
```

## What else the new box needs

- the **dial shim** unit — `public_html/hivv-dial.service` in this repo.
  The agent's own unit is generated by `install-hivv.sh`; the dial's is
  not, which is why it lives here.
- a **local model** on 8080-8082, or a network-backed door. The hive
  routes to whatever can answer; a bee with no brain answers slowly.
- the **session secret**, if this box is also going to serve the gateway.
  It signs session cookies, and a cookie signed by the old box is
  rejected by the new one — which looks exactly like "my sessions keep
  logging me out".

## The bee's own doors

`node-state.sh` reports which doors are open:

```
==> local doors
  door.shard_api             listening on 18090
  door.local_llm             listening on 8090
  door.dial                  listening on 3911
```

- **`door.shard_api`** — a KwaaiNet node serving an OpenAI-compatible API
  on 18090. The model is resolved through the **network**, not on this box:
  it finds a covering block chain through the hivemind DHT per request, so
  an answer can come from any node serving that model.
- **`door.local_llm`** — a local llama.cpp server, the fallback when the
  network cannot answer.
- **`door.dial`** — the bee's own OpenAI-compatible port.

A bee with all three closed is a bee the hive can reach but not ask.
